ERROR REPORT 1: Negative Next Period Countdown Displayed in Mobile App UI
Source: cycle_tracking_report.html (Test Run History & Cycle Algorithm Simulator)
Category: App UI Computation Defect
Severity: Critical
Total Affected Runs: 82 of 82 Runs
================================================================================

1. ERROR DESCRIPTION
--------------------------------------------------------------------------------
On the Curapod mobile app home dashboard and Cycle Tracking screen, the 
"NEXT PERIOD" metric renders an invalid negative countdown string (for example, 
"In -74 days", "In -73 days", "In -44 days", "In -12 days").
Meanwhile, both reference clinical algorithms (1st Algo and 2nd Algo) compute 
valid, positive future countdowns (such as "In 1 days", "In 7 days", "In 14 days").


2. ROOT CAUSE ANALYSIS (WHY IT FAILED)
--------------------------------------------------------------------------------
1. No Forward Recurrence Projection on Mobile UI:
   When a user inputs a past cycle (for instance, a cycle in July 2026), the mobile 
   app UI calculates the remaining days to the next period by performing a raw date 
   difference between the entered historical cycle end date and the device's current date:
   `countdown = (historical_next_period_date - current_device_date).days`
   Since the entered date was months in the past, this arithmetic produces a negative number 
   (e.g., -73 days), which the app naively formats into "In -73 days".

2. Divergence from Clinical Algorithm:
   Both the first algorithm (`cycle_predictor_algorithm.py`) and second algorithm 
   (`second_cycle_algorithm.py`) correctly forward-project subsequent cycles using 
   the user's average cycle length until a cycle boundary in the present or future is 
   reached. The app client completely lacks this forward projection engine.

4. EXPECTED VS ACTUAL BEHAVIOR
--------------------------------------------------------------------------------
EXPECTED:
  The app UI should project cycles forward and display a positive, valid countdown:
  e.g. "In 7 days", "In 1 days", "In 14 days". Under no circumstances should a 
  negative number ("In -XX days") ever be displayed to the end user.

ACTUAL:
  The app UI displays "In -XX days" across 82 test runs.


5. RECOMMENDED FIX
--------------------------------------------------------------------------------
1. In the mobile app's cycle calculation module, add a recurring cycle projector:
   While `projected_next_period < today`:
       `projected_next_period += avg_cycle_length_days`
2. Apply a validation guard on the UI label formatting:
   If `days_until_next < 0`, trigger recalculation or display "Period overdue" 
   instead of formatting a negative integer into "In -XX days".
