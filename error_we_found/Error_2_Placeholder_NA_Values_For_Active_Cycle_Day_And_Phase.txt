Total Affected Runs: 56 of 82 Runs

1. ERROR DESCRIPTION
--------------------------------------------------------------------------------
In 56 test runs in the HTML report, the mobile app UI displays 
uninitialized placeholder text:
- `YOU ARE IN`: displays "- day of cycle" or "N/A"
- `CYCLE TRACKING`: displays "N/A"
Meanwhile, the clinical algorithms calculate active metrics (such as "Day 10", 
"Day 15", "Day 18") and active phases ("Fertile", "Luteal", "Menstruation").


2. ROOT CAUSE ANALYSIS (WHY IT FAILED)
--------------------------------------------------------------------------------
1. Disconnected State Initialization:
   When new cycles are saved during user onboarding or via direct cycle setup, 
   the app's local database does not bind the calculated cycle day and phase to 
   the Home dashboard UI card. It renders the default uninitialized string templates:
   `"- day of cycle"` and `"N/A"`.

2. Failure to Determine Current Cycle Phase:
   Because the app failed to forward-project past cycle entries into the current month,
   the current calendar date falls outside the single historical period window stored 
   in memory. Consequently, the phase classifier returns `null`/`N/A`.

--------------------------------------------------------------------------------

  The app UI should display the active cycle day (e.g., "Day 10", "Day 5") and

ACTUAL:
  The app UI displays placeholder text "- day of cycle" and "N/A".


5. RECOMMENDED FIX
--------------------------------------------------------------------------------
1. Implement forward-projection in the client-side state manager so that current date 
   is always mapped to a cycle day between 1 and `avg_cycle_length`.
2. Connect the cycle phase evaluator to the projected cycle day to populate the 
   `CYCLE TRACKING` card instead of falling back to "N/A".
