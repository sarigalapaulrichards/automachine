ERROR REPORT 3: Stale Historical Dates Displayed For LAST PERIOD & EST. NEXT
Source: cycle_tracking_report.html (Test Run History & Cycle Algorithm Simulator)
Category: App UI Recurrence & Date Calculation Defect
Severity: High
Total Affected Runs: 78 of 82 Runs
================================================================================

1. ERROR DESCRIPTION
--------------------------------------------------------------------------------
In 78 test runs, the mobile app UI displays historical dates from months 
prior (for example, LAST PERIOD: "Jul 11", EST. NEXT: "Jul 27" or "Aug 25") 
even though testing is running in October 2026.
In contrast, both clinical algorithms forward-project recurrence and identify the 
most recent period date (e.g., "Sep 29", "Oct 04", "Sep 27") and upcoming next 
period date (e.g., "Oct 15", "Oct 21", "Oct 23").


2. ROOT CAUSE ANALYSIS (WHY IT FAILED)
--------------------------------------------------------------------------------
1. Raw Historical Echoing:
   The mobile application displays the exact user input dates entered during test setup 
   (e.g., 'Jul 11') as `LAST PERIOD` instead of computing the most recent recurring 
   period start that occurred before the current date.

2. Static Next Period Estimation:
   The app adds `stepper_cycle_length` to the single historical start date once, 
   producing an `EST_NEXT` that is still in the past (e.g. `Jul 27`), rather than 
   chaining recurrence to find the true next occurrence in October.

4. EXPECTED VS ACTUAL BEHAVIOR
--------------------------------------------------------------------------------
EXPECTED:
  `LAST PERIOD` must reflect the most recent cycle start date prior to today.
  `EST. NEXT` must reflect the future projected period start date.

ACTUAL:
  Both fields display obsolete dates that occurred months ago.


5. RECOMMENDED FIX
--------------------------------------------------------------------------------
1. Calculate `last_period_start` as the maximum period start date `<= current_date`.
2. Calculate `est_next_period` as `last_period_start + avg_cycle_length`.
